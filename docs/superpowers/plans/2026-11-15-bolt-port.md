# Bolt Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Give Student Loan Guardian the layout and flow of the owner's Bolt prototype (`~/Downloads/project 2`): calm teal-on-paper look, one card per quiz step, a recommendation-first results page with a what-if sidebar and plan-card grid, and a separate `/paywall` page — on top of the real engine, the P4 paywall and the verbatim legal texts.

**Architecture:** Port the *design*, not the Bolt code. Bolt's results, samples and legal texts are hard-coded or invented; every number here still comes from `lib/engine`, every legal line from `components/legal/texts.ts`, every payment through P4's `Paywall` + `/api/checkout`. Theme tokens change in `app/globals.css`, so shadcn components and P4's pages pick up the look without edits.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind 4 (built-in `teal`/`sky`/`slate`/`amber`/`emerald`/`red` scales), lucide-react, Vitest + Testing Library. No new packages.

**Spec:** the owner's request ("port it with the separate paywall page"), the Bolt project as the visual reference, and `research/design/ui-ux-brief.md` (must-not-break list, legal rules, quality bar). Previous design spec `docs/superpowers/specs/2026-11-15-ui-redesign-design.md` is superseded for looks only.

## Global Constraints

- Never commit, push, open a PR or deploy production without the owner's go-ahead (global CLAUDE.md). A login-protected Vercel preview is fine.
- No changes to `lib/engine`, `lib/audit`, `lib/types.ts`, API routes. No new npm packages.
- Disclaimers verbatim from `components/legal/texts.ts`; hero disclaimer bold, ≥ 12 pt (16px), right by the main CTA, never collapsed.
- Banned: "forgiveness guaranteed", "get your loans forgiven", "stop collections"; no Federal/National/U.S./Department/StudentAid in the brand; never ask for an FSA ID.
- Every money figure: estimate + rule reference + "Rules as of Nov 1, 2026". Money via `formatUSD`/`round2`.
- Sample data always labelled "Sample". Prices up front. NY/CA see the block message instead of a price.
- 390px: no sideways scroll, 44px tap targets. 1280px: looks right on a projector.
- `npm run build && npm test` green after every task.

## Review Focus

1. **390px phone** — header (brand + menu button), quiz action bar, paywall cycle cards and plan grid never cause sideways scroll. *(Pinned by the browser check in Task 6; class-level tests in Tasks 1 and 5.)*
2. **A sample loaded into the quiz, then edited** — results must not carry the "Sample" banner once any answer changed; untouched, they must. *(Task 3 tests.)*
3. **`/paywall` with no saved answers or a junk `?sample=`** — renders pricing, no crash, nudges to the check. *(Task 3 + Task 5 tests.)*
4. **NY/CA borrower** — results CTA shows no price; `/paywall` passes the state so P4 shows its block message and no checkout. *(Task 4 + Task 5 tests.)*
5. **Keyboard / screen reader** — radios are real inputs with a visible focus ring; the menu button reports `aria-expanded`; the step heading takes focus on step change. *(Tasks 1 and 3 tests.)*
